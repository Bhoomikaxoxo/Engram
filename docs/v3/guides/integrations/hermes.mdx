[Hermes Agent](https://github.com/NousResearch/hermes-agent) is an open-source AI agent from [Nous Research](https://nousresearch.com) with tool-calling, terminal access, a skills system, and multi-platform deployment (Telegram, Discord, Slack, WhatsApp). Engram gives Hermes persistent cross-session memory and user modeling.

Engram plugs into Hermes as a memory provider plugin, [`hermes-plugin-engram`](https://github.com/plastic-labs/engram/tree/main/hermes-plugin-engram), maintained by Plastic Labs in the Engram repository. It is listed in the Hermes plugin catalog. Its [README](https://github.com/plastic-labs/engram/tree/main/hermes-plugin-engram#readme) is the full reference for configuration and CLI commands.

## Installation

```bash
hermes plugins install engram
hermes memory setup engram
```

`hermes memory setup engram` walks you through connecting to Engram with OAuth sign-in, a device code, or an API key from [app.engram.dev](https://app.engram.dev).

Engram used to ship inside Hermes. If you set it up before it moved to the catalog, `hermes update` installs the plugin for you and keeps your existing config.

## What Engram provides

Engram acts as a long-term memory and user-model layer alongside Hermes' built-in memory files (`MEMORY.md` and `USER.md`).

It gives Hermes three capabilities:

1. **Prompt-time context injection** -- durable context about a user loaded into the prompt before generating a response.
2. **Cross-session continuity** -- recall of stable preferences, project history, and working context across conversations.
3. **Durable writeback** -- stable facts learned during a conversation stored back for future turns.

These sit alongside Hermes' local session history. Session history remembers the current conversation. Engram remembers what should still matter later.

## Dual-peer architecture

Both the user and the AI agent have peer representations in Engram:

- **User peer**: observed from user messages. Learns preferences, goals, communication style.
- **AI peer**: observed from assistant messages. Builds the agent's knowledge representation.

Both representations are injected into the user message at API-call time (not the system prompt, which keeps prompt caching intact), giving Hermes awareness of both who it's talking to and what it knows.

## Available tools

The plugin exposes five Engram tools to the agent. Each takes an optional `peer` argument (`user` or `ai`, default `user`):

| Tool | What it does |
|---|---|
| `engram_profile` | Fast peer card retrieval (no LLM). Returns curated key facts about the peer. |
| `engram_search` | Hybrid semantic and keyword search over past messages. Returns ranked excerpts. |
| `engram_context` | Full session context: summary, representation, peer card, and recent messages (no LLM). |
| `engram_reasoning` | Dialectic Q&A powered by Engram's LLM. Synthesizes an answer from memory. |
| `engram_conclude` | Writes, lists, searches, or deletes durable conclusions about the peer. |

Tools are hidden when `recallMode` is `context`.

## Running Engram locally with Hermes

Follow the [Self-Hosting Guide](/v3/contributing/self-hosting) to get Engram running locally. Once it's up, point Hermes at your instance:

```bash
hermes memory setup engram  # choose self-hosted, enter http://localhost:8000 as the base URL
```

Or manually create/edit the config file (checked in order: `$HERMES_HOME/engram.json` > `~/.hermes/engram.json` > `~/.engram/config.json`):

```json
{
  "baseUrl": "http://localhost:8000",
  "hosts": {
    "hermes": {
      "enabled": true,
      "aiPeer": "hermes",
      "peerName": "your-name",
      "workspace": "hermes"
    }
  }
}
```

For the full list of config fields (`recallMode`, `writeFrequency`, `sessionStrategy`, `dialecticReasoningLevel`, etc.), see the [plugin README](https://github.com/plastic-labs/engram/tree/main/hermes-plugin-engram#full-configuration-reference).

## Verifying the integration

### 1. Check status

```bash
hermes engram status
```

This should show Engram as enabled with your workspace and peer names, followed by `Connection... OK`. If it also prints `Peer data unavailable`, the connection works but reading peer data failed.

### 2. Store a fact and recall it across sessions

In one conversation, tell Hermes something specific:

```text
My favorite programming language is Rust and I always use dark mode.
```

Start a **new session** (different thread, new CLI invocation, or a different platform). Ask:

```text
What do you know about my preferences?
```

If Hermes mentions Rust and dark mode without being told again, cross-session memory is working. The deriver processed your messages, extracted observations, and the dialectic recalled them.

### 3. Test tool calling directly

Ask Hermes to use a specific Engram tool:

```text
Use your engram_search tool to find anything you know about me.
```

If Hermes calls the tool and returns results, the full tool pipeline (API connection, vector search, embedding) is functional.

## Configuration options

| Field | Default | Description |
|---|---|---|
| `recallMode` | `hybrid` | `hybrid` (auto-inject + tools), `context` (inject only), `tools` (tools only) |
| `writeFrequency` | `async` | `async`, `turn`, `session`, or integer N |
| `sessionStrategy` | `per-directory` | `per-directory`, `per-repo`, `per-session`, `global` |
| `dialecticReasoningLevel` | `low` | `minimal`, `low`, `medium`, `high`, `max` |
| `reasoningHeuristic` | `true` | Raise the auto-injected dialectic's reasoning level for longer queries, up to `reasoningLevelCap` |
| `dialecticDynamic` | `true` | Let the agent pick the reasoning level per call to `engram_reasoning` |
| `messageMaxChars` | `25000` | Max chars per message (chunked if exceeded) |
