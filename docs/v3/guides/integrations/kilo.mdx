Give Kilo Code long-term memory that survives context wipes, session restarts, and fresh chats. Kilo remembers what you're working on, your durable preferences, and prior context across every project you touch. The plugin runs inside Kilo's local server, so the same install works in the Kilo CLI, the VS Code extension, and the JetBrains plugin.

## Quick Start

### Step 1: Get Your Engram API Key

1. Go to **[app.engram.dev](https://app.engram.dev)**
2. Sign up or log in
3. Copy your API key (starts with `hch-`)

### Step 2: Install the Plugin

<Tabs>
  <Tab title="Desktop app, VS Code, JetBrains">
    Install **Engram** from the Kilo Marketplace, then type `/engram` in the chat. The agent asks what name Engram should call you and opens a window on your screen for your API key. You can skip Step 3. See [Setting Up from the Desktop App or an Extension](#setting-up-from-the-desktop-app-or-an-extension).

    <Note>
    Until Engram is listed in the Kilo Marketplace, add it to Kilo's global config yourself. Put it in the `plugin` array of `~/.config/kilo/kilo.jsonc`, and create the file if it does not exist:

    ```jsonc
    {
      "plugin": ["@engram-ai/kilo-engram"]
    }
    ```

    Restart Kilo, then type `/engram`.
    </Note>
  </Tab>
  <Tab title="Kilo CLI">
    Install the plugin, then run Step 3:

    ```bash
    kilo plugin @engram-ai/kilo-engram --global
    ```
  </Tab>
</Tabs>

To update an existing install:

```bash
kilo plugin @engram-ai/kilo-engram --global --force
```

To add the plugin by hand, put `"@engram-ai/kilo-engram"` in the `plugin` array of `~/.config/kilo/kilo.jsonc` (or `kilo.json`), which loads the server half, and of `~/.config/kilo/tui.json`, which loads the `/engram:*` commands. `kilo plugin` writes the same entries, but under Kilo's older `opencode.json` name; Kilo reads both. The desktop app and the VS Code and JetBrains extensions read the same global config, so one install covers every client.

### Step 3: Run Setup in the Kilo CLI

1. Start Kilo. The first time the plugin loads without an API key, it offers to set up Engram.
2. Choose **Set up now**, or run `/engram:setup`
3. Keep the default **Engram Cloud** option unless you want a self-hosted or local endpoint
4. Paste your Engram API key
5. Confirm the name Engram should call you. Setup fills in the `peerName` your other Engram tools use, or your OS user name.
6. Choose a workspace: Kilo's own, or one another Engram tool already uses
7. Run `/engram:status` to verify the runtime

<Tip>
Already using Engram with Claude Code, Hermes, or another tool? Kilo reads the same `~/.engram/config.json`, so it works without setup. Run `/engram:setup` only to share a workspace with that tool.
</Tip>

## What You Get

- **Persistent Memory** — Kilo retains durable context across sessions
- **Recall on every prompt** — Engram's conclusions that match your prompt reach the model without being saved into Kilo's session history
- **Visible recall** — A Engram section in Kilo's sidebar shows what Engram added, and `/engram:recall` shows the exact text
- **Cloud or Local Deployments** — Point at Engram Cloud or a self-hosted / local instance
- **Flexible Session Mapping** — Scope sessions per directory, repo, branch, chat instance, or globally
- **Memory Skill** — A `engram-memory` skill tells the agent when to search and save memory on its own
- **Agent Tools** — First-class tools for search, chat, and conclusion-writing inside Kilo

## Kilo CLI, Desktop App, and IDE Extensions

Every Kilo client starts its own local Kilo server, and the plugin runs inside that server. Memory works the same in all of them: Engram recalls what it knows about you on each prompt, saves the conversation, and gives the agent its `engram_*` tools. Setup and what you can see differ.

| | Kilo CLI | Desktop app, VS Code, JetBrains |
| --- | --- | --- |
| Recall, saving, and `engram_*` tools | Yes | Yes |
| Setup | `/engram:setup`, or **Set up now** when Kilo first loads the plugin | `/engram`, or say yes when the agent offers |
| `/engram` command | Yes | Yes |
| Engram section in the sidebar | Yes | No |
| `/engram:*` commands | Yes | No |
| Check that Engram is working | The sidebar, `/engram:status`, `/engram:recall` | `/engram`. Engram tool calls also appear in the chat. |

The sidebar section and the `/engram:*` commands come from the plugin's terminal UI half. The desktop app and the extensions do not load terminal UI plugins. `/engram` comes from the server half, so every client lists it.

### Setting Up from the Desktop App or an Extension

Type `/engram` in the chat. The agent asks what name Engram should call you, then opens a window on your screen for your API key. Paste the key into that window, never into the chat. Memory starts with your next message; you do not need to restart Kilo. Asking "Set up Engram memory for me" does the same, and the agent offers it on its own when Engram has no key.

Once Engram is set up, `/engram` shows your peer, the workspace, a link to the session, and a summary of what Engram recalled most recently. `/engram` is a prompt to the agent, so it uses a model call.

If the window cannot open, for example in a remote session, see [Remote and Headless Use](#remote-and-headless-use).

### Differences Outside the CLI

- **Environment variables.** On macOS and Linux, the desktop app and an editor opened from the Dock or an app launcher do not see variables from your shell profile, such as `ENGRAM_API_KEY` in `~/.zshrc`. Save the key with setup instead. An editor started from a terminal, for example with `code .`, does see them.
- **Desktop chats.** Each desktop chat runs in its own folder, so each chat is its own Engram session. Memory of you carries across chats. `engram_search` searches the current session's messages only, so it finds nothing from other chats; `engram_chat` and recall do.
- **Kilo version.** The desktop app and the extensions bundle their own copy of Kilo, which can be a different version from your Kilo CLI. All of them read the same `~/.config/kilo` and `~/.engram/config.json`, so one install and one setup cover every client.

## Kilo Memory and Engram

Kilo has its own memory feature, Kilo Memory. It is off by default, and it stores facts about the current project on your machine. Engram stores facts about you, and keeps them across every repo and every machine that uses the same workspace. The two run side by side. Kilo Memory's capture skips the text this plugin adds, so Engram's recall is never copied into Kilo Memory.

Kilo's sidebar shows `Memory • Disabled` while Kilo Memory is off. That line is about Kilo Memory only. The plugin adds its own Engram section below it:

```
Engram
• Active
Peer: alice
Session: View in Engram ↗
/engram:recall
```

On Engram Cloud, clicking `View in Engram` opens the session in the Engram dashboard, where you can read the saved messages and the conclusions. Any other Engram server has no known dashboard address, so the sidebar shows the session name instead. Click `/engram:recall`, or run it, to read the exact memory text the model received.

<Note>
The sidebar section is part of the Kilo CLI. The desktop app and the IDE extensions do not show it; see [Kilo CLI, Desktop App, and IDE Extensions](#kilo-cli-desktop-app-and-ide-extensions).
</Note>

## Configuration

Configuration lives in a single shared file at `~/.engram/config.json`, shared with other Engram hosts (Claude Code, Codex, OpenCode, and others). Kilo-specific settings live under `hosts.kilo`. Edit the file directly, use `/engram:config`, or call the `engram_set_config` tool.

```jsonc
{
  "apiKey": "hch-...",
  "peerName": "alice",
  "baseUrl": "https://api.engram.dev",
  "hosts": {
    "kilo": {
      "workspace": "kilo",
      "aiPeer": "kilo",
      "recallMode": "hybrid",
      "observationMode": "unified",
      "sessionStrategy": "per-directory"
    }
  }
}
```

Top-level shared fields are `apiKey`, `peerName`, and `baseUrl`. Kilo's host-scoped settings live under `hosts.kilo`: `workspace`, `aiPeer`, `recallMode`, `observationMode`, `agentObserveMe`, `autoConclusions`, and `sessionStrategy`. Set `KILO_ENGRAM_CONFIG_PATH` to use a different file.

`autoConclusions` is off by default. When it is on, a prompt that contains phrases such as "I prefer", "always", "never" or "remember that" is saved verbatim as a conclusion, so it is available on the next prompt. Engram already derives conclusions from every saved message, and the keyword rule also catches prompts like "never mind, revert that".

### Peer Name and Workspace

Your peer is your `peerName`, unchanged, so Kilo uses the same peer as your other Engram tools. Kilo reads `ENGRAM_PEER_NAME`, then `peerName` in `~/.engram/config.json`, then your OS user name (`$USER`). If you already use another Engram tool, Kilo picks up its API key and peer name with no setup.

A peer belongs to one workspace. Kilo uses its own `kilo` workspace by default, so it starts with no memory of you. To share memory with another Engram tool, choose that tool's workspace in `/engram:setup`, or set `hosts.kilo.workspace` to it. This changes nothing for the other tool.

### Cloud vs Local

For **Engram Cloud**:

- `apiKey` is required
- `baseUrl` should stay at `https://api.engram.dev`

For **self-hosted or local Engram**:

- `baseUrl` should point to your deployment (e.g. `http://127.0.0.1:8000`). Without `baseUrl`, Kilo uses the `environmentUrl` that `engram init` writes.
- `apiKey` is only required if the deployment is authenticated
- The agent's `engram_setup` will not switch Kilo to a local `baseUrl`. Set it in the file, or with `/engram:setup` in the Kilo CLI.

<Warning>
If Kilo is running inside Docker or another remote environment, `localhost` won't refer to your host machine. The `baseUrl` must be reachable from the Kilo server.
</Warning>

### Recall Modes

| Mode | Behavior | Best for |
| --- | --- | --- |
| `hybrid` (default) | Context injection **and** tool access | Most users — balanced memory coverage |
| `context` | Only inject memory into the prompt | Predictable prompts, no tool calls |
| `tools` | Only expose memory as tools | Explicit, on-demand retrieval |

### Session Strategies

| Strategy | Behavior | Best for |
| --- | --- | --- |
| `per-directory` (default) | One session per working directory | Most projects |
| `per-repo` | One session per repository | Repos with multiple entry directories |
| `git-branch` | Session follows the current git branch | Branch-specific workflows |
| `per-session` | New session per Kilo session id | Short-lived isolated work |
| `chat-instance` | Session tied to the current chat instance | Highly ephemeral usage |
| `global` | One session for everything | Shared memory across all work |

## Operator Commands

| Command | Description |
| --- | --- |
| `/engram` | Set up Engram from the chat, or show your peer, workspace, session link, and latest recall. Every Kilo client lists it. |
| `/engram:setup` | First-time setup for cloud or local Engram |
| `/engram:status` | Show effective Engram status for the current Kilo project |
| `/engram:recall` | Show the exact memory text Engram added to the current session |
| `/engram:settings` | Show effective config values and config paths |
| `/engram:config` | Edit shared Engram fields |
| `/engram:import` | Preview or import local Kilo session history into Engram |

The `/engram:*` commands are part of the Kilo CLI only.

## Agent Tools

The plugin exposes these tools inside Kilo:

| Tool | Description |
| --- | --- |
| `engram_setup` | Save the peer name and workspace, and ask for the API key in a window on the user's screen. A key never passes through the chat, and the saved key is never sent to a new server. |
| `engram_status` | Show effective runtime status |
| `engram_get_config` | Read effective and persisted settings |
| `engram_set_config` | Update a persisted shared setting. `apiKey` and `baseUrl` can only be changed by the user. |
| `engram_search` | Search the messages in the current Engram session only |
| `engram_chat` | Query Engram for reasoning-backed context |
| `engram_create_conclusion` | Save a durable memory conclusion |

The agent cannot read Engram's config. The plugin refuses any Kilo tool call that names `~/.engram`, the config file in use, or the session activity folder, and tells the agent to call `engram_status` instead. It checks file paths and command text, so it stops an agent that means well, but not one that hides the path on purpose.

## What Install Writes

- **Kilo config:** `@engram-ai/kilo-engram` in the `plugin` array of Kilo's global config. `kilo plugin --global` writes it to `~/.config/kilo/opencode.json` and `~/.config/kilo/tui.json`. The Kilo Marketplace adds the same `plugin` entry.
- **Engram config:** `~/.engram/config.json`, written only by `/engram:setup`, `/engram:config`, `engram_setup`, and `engram_set_config`, with mode 600. Installing or starting the plugin does not write it. An `apiKey` written as `${ENGRAM_API_KEY}` stays a reference.
- **Skill:** `~/.config/kilo/skills/engram-memory/SKILL.md`, or `$XDG_CONFIG_HOME/kilo/skills/engram-memory/SKILL.md` when that variable is set. Every Kilo client reads it.
- **Import state:** `~/.engram/kilo-import-state.json`, after you run `/engram:import`.
- **Session activity:** `~/.engram/kilo/sessions/<session id>.json`, one file per Kilo session, with mode 600. It holds the memory text shown by `/engram:recall`. Files older than 14 days are removed when the plugin starts, and a file is removed when Kilo deletes its session.

## Troubleshooting

**The plugin does not load.** Run `kilo run --print-logs "hello"` and look for `kilo-engram` and `Engram session initialized for Kilo.` in the output. Setting `KILO_PURE=1` turns off every external plugin, including this one.

**Kilo does not use memory.** In the desktop app or an extension, type `/engram`. In the CLI, check the Engram section in the sidebar. `Not set up` means there is no API key: run `/engram:setup`. `Error` shows the reason the last Engram request failed. Run `/engram:status` to see the values the plugin uses, including any `ENGRAM_API_KEY`, `ENGRAM_URL`, or `ENGRAM_WORKSPACE` set in your environment. Recall starts once Engram has something to recall; a new workspace has no conclusions until a few messages have been processed.

**The sidebar shows the wrong peer.** Kilo uses `ENGRAM_PEER_NAME` if it is set, then `peerName` from `~/.engram/config.json`, then your OS user name. Unset `ENGRAM_PEER_NAME` or run `/engram:setup` to choose a name. Every Engram tool on the machine reads it from `~/.engram/config.json`.

**The sidebar shows `Error: … could not be read`.** `~/.engram/config.json` is not valid JSON. Engram pauses until you fix the file, then resumes with the next message.

**Memory is missing from another tool.** Each tool writes to its own workspace unless you set the same `workspace` for both. See [Configuration](#configuration).

## Remote and Headless Use

The plugin runs wherever Kilo's server runs, and reads `~/.engram/config.json` on that machine. When no window can open on your screen, finish setup on that machine in one of two ways:

- Run `/engram:setup` in the Kilo CLI there, if that machine has it.
- Write `~/.engram/config.json` yourself with at least `apiKey` and `peerName` (see [Configuration](#configuration)), then run `chmod 600 ~/.engram/config.json`.

- **VS Code Remote SSH, dev containers, Codespaces.** Kilo's server runs on the remote machine, so it reads the remote's `~/.engram/config.json`, not your laptop's. Set Engram up on the remote.
- **Key window over SSH.** On macOS and Windows, `engram_setup` does not open the key window in an SSH session, because it would appear on that machine's own screen. The agent tells you to finish setup one of the two ways above instead. On Linux it opens only when a display is available, including through X forwarding. An unanswered window closes after 2 minutes.
- **CI and scripts.** When the `CI` variable is set, the agent does not offer setup. Set `ENGRAM_API_KEY` to use Engram in CI, or `KILO_PURE=1` to turn off every plugin.

## Building with Teammates

Because `~/.engram/config.json` is shared across Engram hosts, teammates can point at the same workspace while keeping their own identities. Session names start with each person's peer, so two teammates in the same repo never share a session.

**Alice** (`~/.engram/config.json`):
```json
{
  "apiKey": "hch-team-key...",
  "peerName": "alice",
  "hosts": {
    "kilo": { "workspace": "team-acme", "aiPeer": "kilo" }
  }
}
```

**Bob** (`~/.engram/config.json`):
```json
{
  "apiKey": "hch-team-key...",
  "peerName": "bob",
  "hosts": {
    "kilo": { "workspace": "team-acme", "aiPeer": "kilo" }
  }
}
```

Both write to `team-acme`; Engram's dialectic reasoning draws on context from both peers.
